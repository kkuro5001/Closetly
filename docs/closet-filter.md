# クローゼットの絞り込み・並び替え

## 作ったもの
- `frontend/lib/utils/closet_filter.dart`: 絞り込み・並び替えの純粋ロジック(`ClosetFilter`、`ClosetSort`、`availableCategories/Seasons/Colors`)
- `frontend/lib/pages/closet_page.dart`: グリッド上部にフィルタチップ(種類・季節・色)、並び順ドロップダウン、「絞り込みを解除」ボタン、0件表示を追加
- `frontend/test/closet_filter_test.dart`: ロジックの単体テスト(14件)

## 設計判断
- **クライアント側で絞り込む(Supabaseの`.eq()`は使わない)**: クローゼットは全件を読み込み、画像URLを毎回署名し直す(バケットがprivate)。サーバー側で絞ると、チップを触るたびに再取得・全URL再署名が走り遅く、通信も増える。読み込み済みリストをメモリ上で絞れば即時に反映され、署名済みURLも `FutureBuilder` の再生成だけで済む。服の数が数千件規模になったら、ページング+サーバー側絞り込みを再検討する。
- **3項目とも複数選択**: 同じ項目内はOR(「Tシャツ or パンツ」)、項目どうしはAND。「夏の黒い服」「トップス類をまとめて」のような探し方に対応でき、単一選択より自然なため。
- **チップは実在する値のみ**: 0件になる選択肢を出さないため、読み込んだデータに存在するカテゴリ・季節だけを表示。順序は `clothing_options.dart` の定義順で、定義にない値(過去データ等)は末尾に出す。色は自由入力なので出現した値を前後空白除去・重複排除して辞書順で表示する。
- **並び順**: 新しい順(デフォルト)/古い順/カテゴリ順(定義順、同カテゴリ内は新しい順)。`createdAt` が無い行は最も古い扱い、同時刻は id で安定化。
- **状態の保持**: フィルタは `_ClosetPageState` のフィールドなので、詳細ページへ遷移して戻っても保持される。再読み込み(削除後・更新)時は、存在しなくなった値を選択から自動で外す(外さないと、削除で最後の1着が消えた後に結果が0件のまま解除できない状態になる)。
- **空状態の区別**: 服が1着もない場合は従来の「まだ服が登録されていません」、絞り込みで0件なら「条件に合う服がありません」+「絞り込みを解除」ボタン。
- 既存のレスポンシブグリッド(`maxCrossAxisExtent: 200`)、リフレッシュ(`RefreshIndicator`/AppBarボタン)、削除後の再読み込みはそのまま。
