# 着用記録(服ごとの「今日着た」とホームの集計)

## 作ったもの
土台(`wear_logs` テーブル、`WearLog` モデル、`WearLogService`)の上に、着用記録の UI と集計を載せた。

- 服の詳細画面に「着用」欄: 着た回数・最後に着た日・「今日着た」ボタン(今日の記録があれば「今日の記録を取り消す」に変わる)
- ホーム画面に 2 枚のカード: 「しばらく着ていない服(30日以上)」と「よく着る服(上位5着、回数つき)」。どちらも横スクロールのサムネイルで、タップで詳細へ
- 集計は UI 非依存の純粋関数として `frontend/lib/utils/wear_stats.dart` に置いた。テストは `frontend/test/wear_stats_test.dart`

## 設計判断
- 「今日」は引数で受け取る: `staleClothes(clothes, logs, today)`。関数の中で `DateTime.now()` を呼ばないので、テストで日付を固定できる。画面側は端末のローカル日付(`DateTime.now()`)を渡す。DB の `current_date` は UTC なので使わない(土台の方針どおり)。
- 日数の数え方: `daysBetween` は両方を `DateTime.utc(y, m, d)` にして差を取る。ローカル時刻のまま `difference` すると夏時間で 23/25 時間の日があり、`inDays` がずれうるため。
- 「しばらく着ていない」の基準日: 最後に着た日。一度も着ていなければ登録日(`createdAt`)。ちょうど N 日(30日)は含み(`>=`)、29日は含めない。登録したばかりの未着用の服は含めない。`createdAt` が null で記録も無い服は判断材料が無いので含め、基準日不明として一覧の先頭に出す。`id` が null の服は着用記録と結びつけられないので無視。並びは基準日の古い順。
- 「よく着る服」: 回数の降順、同数なら最後に着た日が新しい順。0回の服は含めない。上位 `limit`(既定5)件。
- 詳細画面の「着用」欄のエラー分離: 着用記録の読み込みは服の表示とは独立した try/catch にし、失敗(テーブル未作成など)しても編集・削除・画像表示は動く。欄には「着用記録を読み込めませんでした」と再読み込みボタンだけを出す。
- 連打防止: `isWearBusy` の間は「今日着た」ボタンを無効にし、関数の先頭でも弾く。記録・取り消し後は DB から取り直して表示を確定させる(クライアントで推測しない)。
- 一覧・ホームへの反映: 記録・取り消しに成功したら既存の `edited = true` を立てる。戻るときに `true` が返り、クローゼットとホームが再読み込みする(ホームのサムネイルは `true` で `loadClothes()`)。
- ホームでの失敗の分離: `loadClothes` は服の取得に成功したあと、着用記録を別の try/catch で取る。失敗したら `wearError` に入れ、合計・カテゴリ別・色別・季節のカードは通常どおり出し、着用 2 カードだけエラー表示にする。服の取得自体の失敗は従来どおり全体エラー。
- 詳細画面の本文を `SingleChildScrollView` にした: 着用欄を足して縦に伸び、画像 350px と合わせて小さい画面で溢れるため。
- 土台のコード(モデル・サービス・SQL)は変更していない。

## 発生した問題と対処
- 作業開始時、worktree に土台コミット(`76522fb`)が入っていなかったので `git merge feature/wear-log-outfits` で取り込んだ。
- 複数ファイルを一括で書き出すシェルコマンドが「複雑すぎる」として拒否された。ファイル作成は Write ツール、置換は単一の Python スクリプトに分けて対応。
- `flutter pub get` 相当の実行で `linux/macos/windows` 配下の生成ファイルが変わる場合があるため、コミット前に差分を確認する。
